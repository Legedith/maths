# Subject browser integration contract

The `/subjects` view exposes the full pinned MSC2020 classification compiled by `experiments/msc-index/import_msc.py`. The `/subjects/[code]` view shows one subject, its children, original description, source references and their conditions. This is subject navigation. Existing reviewed Atlas concepts, MathGloss identities and formal theorem results are unchanged; no automatic crosswalk is asserted.

The generated files must remain byte-identical to the independently reviewed adapter outputs. The official CSV supplies display labels and descriptions; raw suggested-RDF labels/parents and discrepancy flags remain inspectable. All source strings render as text, including XML/TeX-looking strings. Attribution and CC-BY-NC-SA-4.0 data terms are visible.

Search is lexical, with Unicode NFKC normalization, lowercase conversion and punctuation-to-space normalization. All nonempty query terms must occur in the subject code, official label or description. Ties preserve official source order. No semantic similarity or retrieval-quality claim is made. A query has at most 300 characters. The parent filter is `root`, `all`, or an existing MSC code; pagination is 24 records per page, with a positive integer page at most 1000000. Empty unfiltered browsing shows root subjects. Search forms search all subjects. A parent filter selects immediate navigation children, not all descendants.

The read-only `/api/subjects` GET endpoint accepts either one `code` for a detail result, or at most one each of `q`, `parent`, `page` for a list. Reject unknown parameters, duplicates, mixing detail and list fields, malformed codes, unknown parents and invalid page/query values with HTTP 400 and `Cache-Control: no-store`. Invalid dynamic subject routes show not found. Queries are same-origin GET parameters and may appear in ordinary access logs.

Subject detail preserves outgoing and incoming reference direction. `seeAlso`, `seeMainly` and `seeConditionally` retain their own labels and qualifiers. A reverse navigation link does not reverse the underlying assertion. Collection targets stay collections; their original members are browsable without inventing additional direct references. Every visible source relation retains its source ID and exact RDF predicate/endpoints/qualifier identifiers in API output. The API sends no whole-catalog response. The pinned catalogue must have at most 512 incident references for a subject and 512 members for a referenced collection; reject oversized loaded data instead of silently truncating it.

Validation must traverse all root/child/search pages without losing or duplicating subjects, check every parent and relation endpoint, compare API responses with the pure catalogue functions, and exercise valid and invalid query/detail requests. Verify a condition-bearing cross-domain reference, the collection target, empty leaf, hierarchy discrepancy and exact-label discrepancy displays against data. Run the existing project checks and production build. Source and implementation authors cannot self-certify the final evidence gate.

This view uses server-rendered reading, links and GET forms. It adds no persistent state, external query service or browser mutation tool. Existing WebMCP surfaces remain unchanged. No general visual browser audit is claimed.
