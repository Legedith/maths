# Mathematics Atlas: enduring objective and first milestone

The user authorizes building and tracking work in https://github.com/Legedith/maths. The enduring objective is an expanding map of mathematics and related disciplines, especially computer science, that reveals reusable knowledge, supports verified discovery, guides beginners, and identifies valuable human contributions. A bounded first subset is explicitly allowed. The full objective remains active after any finite milestone.

First milestone must deliver a working interactive knowledge map and reproducible local package, with a focused, source-grounded cross-domain corpus and machine-checkable examples. Choose the first subset by independently comparing cross-domain value, source quality, tractable validation, and usefulness to a beginner. Explore candidate approaches read-only before selection.

Required data semantics: distinguish concept, theorem, method, problem, example, source, and contribution task; typed relations with direction, assumptions, source locator, evidence status, and provenance; distinguish established mathematics, documented proof status, hypotheses/analogies, and corpus gaps. No unsolved label may be inferred from a missing graph edge. Imported formal dependencies, similarity, implication, and equivalence must remain distinct.

Required user workflows: topic/concept search; browse and explain a connection; inspect assumptions and sources; follow a short beginner learning path; identify concrete contribution work; run/review at least one bounded cross-domain computation with independently checkable outcomes. Search and graph traversal must work on real data rather than mock results. It must be possible to add and validate content programmatically.

Evaluation contract: freeze source-independent test fixtures before implementation of the selected mathematical transformation. Use positive, boundary, and negative cases; compare solver results to an independent exhaustive oracle on finite instances; reject out-of-scope assumptions. Search evaluation distinguishes indexed/curated rediscovery from novelty, discloses corpus scope and benchmark construction, includes a plain lexical baseline if any improvement is claimed, and avoids test-label tuning. Retain raw logs, exact commands, seeds, environment, data/code revisions, failed experiments, and results. Do not claim new mathematics or exhaustive coverage without corresponding evidence. New candidate links are proposals until verified.

Writes: shared implementation writes remain serial. Read-only investigators/explorers may run in parallel. The Site-owning root alone edits/deploys the Site. Assign a coe_worker only non-Site backend/data modules, in a serial write window. An independent coe_verifier must inspect raw artifacts and canonical reruns before the milestone is described as verified.

Operational scope: use uv and an isolated Python environment; use local compute and available tools; do not purchase services. Commit meaningful milestones and push to the user-designated repository. Preserve the old temp repository clone. Never expose credentials or publish false mathematical novelty. The requested complete mapping goal cannot be marked complete merely because this first milestone passes.
