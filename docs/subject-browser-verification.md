# Subject browser verification

The pinned source inspection, portable importer and subject browser have passed separate scoped independent reviews. The [source audit](../evidence/msc-classification/source-review/final-audit.json) establishes the source-reuse boundary; the [adapter audit](../evidence/msc-classification/adapter-review/final-audit.json) checks the actual conversion; the [product audit](../evidence/msc-classification/product-review/final-msc-product-audit.json) checks the browser against those approved output bytes. The [evidence bundle](../.codex/evidence/runs/msc-classification-v1/bundle.json) binds the exact artifacts and supported claims.

The importer reviewer independently reconstructed all 6,603 subject records, their physical CSV locators, RDF labels and parents, 2,271 scope-note records, 3,083 direct references, 415 conditional scope records and the sole referenced collection's 62 members. A fresh isolated uv replay reproduced all three JSON files byte-for-byte. Mutations of each of the three pinned processing inputs were rejected, and an existing output directory was left unchanged.

The browser reviewer issued 971 HTTP requests. These traversed all 276 full-catalogue pages, all 598 populated root/immediate-child scopes and five complete lexical searches. Selected details were independently reconstructed from the data, covering conditional references, collection members, disagreements, empty leaves, source text and the largest incident-reference case. Invalid requests, method handling and server-rendered text were also checked. Documentation and CI command alignment passed a separate static review; this does not itself mean a GitHub workflow has run.

The author's final functional run passed 55 checks. The existing Python suite passed 155 tests, and the existing Atlas, graph browser, MathGloss and external-search checks passed. TypeScript, lint and the production build passed. Raw command arguments, selected environment, output, return codes and failed attempts remain in the evidence directories.

Two test corrections are explicit. The author added three TypeScript `Response` annotations in the test harness after type inference errors; runtime behavior did not change, and the corrected functional output is byte-identical to the first passing functional run. The independent browser checker initially misread React's adjacent-text markers and footer attribution; its first failed run and corrected rerun remain retained. The reviewer also requested one product-documentation correction distinguishing detailed API responses from summary list responses.

The upstream Turtle contains an invalid placeholder date, which causes a retained RDFLib warning. The importer does not consume that date. It uses an explicit ISO-8859-1 interpretation of the retained CSV bytes; this is a processing choice rather than a claimed upstream charset declaration. Exact label differences and hierarchy disagreements remain flags, not automatic judgments that the source is mathematically wrong.

Reproduce the importer with the [portable package command](../experiments/msc-index/README.md), then run `node scripts/check-subjects.ts`. Add `--http-origin http://localhost:3000` with the development server running for the author HTTP checks. Use fresh output directories. Historical auditor commands preserve their original D-drive staging paths and do not pretend to be portable scripts.

These reviews establish source fidelity and functional navigation for this snapshot. They do not establish semantic equivalences, prerequisites, a complete mathematical map, an open problem, a discovery, publication novelty, measured real-world impact, Lean verification or general visual/accessibility quality. An earlier certificate does not certify later edits.
